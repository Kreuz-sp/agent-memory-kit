# 生命周期：记忆也会过期

[English](en/03-lifecycle.md) | **简体中文**

## 问题

大部分记忆库只解决「怎么存」，不解决「什么时候该扔、该复核、该降级」。
结果是：条目越积越多，重要的被淹掉，过期的还在被引用。

## 三条元数据

每条 entry 的头部：

```yaml
---
date: 2026-01-01
tier: core | record | raw
review: 2026-07-01      # 到期复核日；raw 可留空
status: active | superseded | archived
supersedes:             # 可选：被这条替代的旧条目
---
```

## 三档

| 档 | 装什么 | 规矩 |
|---|---|---|
| `core` | 事实、决定、承诺、悬案 | 不许丢、不许糊；**必须有 review** |
| `record` | 某天发生了什么 | 写，但不求全；review 默认 6 个月 |
| `raw` | 原文细节、过程来回 | 可以忘；不进索引正文 |

## 三个动作

### 晋升

一条 `record` 被反复引用（比如 ≥3 次），说明它不是「那天的事」，是「一直成立的事」。

→ 人工把它提成 `core`，或者把里面的事实挪进 `facts/`。

### 降级

`core` 过了复核日，且不再被引用。

→ 标 `archived`。**不删**：留着能查，只是不再进上下文。

### 冲突

新事实和旧事实矛盾。

→ 新条目写 `supersedes: 旧条目`，旧条目 `status: superseded`。
**不要直接改旧条目**——改了就看不到「以前是这么认为的」。

## 工具只报告，不自动改

`build_index.py` 会在 `INDEX.md` 顶部列出：

- 到期未复核的条目
- `core` 但没写 review 的条目

它**不会**自动晋升、降级、删除。
因为这三件事都要判断，而判断权在人。

## 最小起步

刚开始可以只用 `record`，不写 `review`。
等条目多到「翻不动」了，再补这一格——**痛感驱动，不靠自觉**。
