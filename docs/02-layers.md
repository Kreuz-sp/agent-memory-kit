# 分层：一条信息该进哪层

[English](en/02-layers.md) | **简体中文**

## 先看图

```
memory/
├─ facts/*.yaml      事实：会被引用、会变、要权威
├─ decisions.md      决定：定了什么 + 为什么
├─ commitments.md    承诺：答应了谁、还欠着
├─ open-threads.md   悬案：没完的事
├─ entries/          记录：某天发生了什么
├─ knowledge/        知识：脱离项目也成立
├─ experience/       经验：跨项目可复用
└─ assets/           材料：原始文件
```

## 判据

| 一条信息的形态 | 放哪 | 问自己一句 |
|---|---|---|
| 会被引用、会变、要权威 | `facts/*.yaml` | 「上次说的是什么」以它为准吗？ |
| 定了什么 + 为什么 | `decisions.md` | 以后会有人问「当时怎么想的」吗？ |
| 答应了谁、还欠着 | `commitments.md` | 不到期就该被看见吗？ |
| 没完的事 | `open-threads.md` | 分得清在等谁吗？ |
| 某天发生了什么 | `entries/` | 能当证据吗？ |
| 换个项目还成立 | `knowledge/` | 脱离上下文仍可执行吗？ |
| 第二次遇到能少走弯路 | `experience/` | 失败方案也写了吗？ |
| 原始文件 | `assets/` | 只存不看吗？ |

**类型不按文件格式分，按「它会被怎么用」分。**

## 几个容易放错的

| 东西 | 容易放错到 | 该放哪 |
|---|---|---|
| 「他说他喜欢先看结论」 | `entries/` | `facts/03_preferences.yaml` |
| 「今天他心情不好」 | `facts/` | `entries/`（而且只写发生的事，不写评价） |
| 「Docker 在 Windows 上要开 WSL2」 | `entries/` | `knowledge/` |
| 「别用 777 改权限」 | `knowledge/` | `experience/`（这是踩过坑才有的判断） |
| 一段聊天截图 | `entries/` | `assets/`，在 entry 里放链接 |

## 库不装人格

人格回答「我是谁、怎么说话」，库回答「什么是真的、发生过什么」。

混在一起会有两个后果：

- 库变成剧本：agent 照着旧台词演，而不是对着眼前的人说话
- 人格变成日志：每天的性格都被当天的情绪覆盖

**所以人格文件放库外**（系统提示词、`AGENTS.md`、`CLAUDE.md` 都行），库里只放事实和记录。

## 一条硬规矩

**没写 `source` 的条目，等于没有。** 来源可以是「用户自述」「对话原话」「终端日志」「某文件第几行」——但不能空着。

## 媒体

`assets/` 里的文件是证据，不是记忆。

- 在 entry 里用相对路径引用；
- 重要的内容要写下来——没人描述过的截图，等于死路；
- 大文件不进 git（或走 Git LFS）；库要小、要能 diff。
