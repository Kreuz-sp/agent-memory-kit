# 一次会话怎么用

[English](en/04-workflow.md) | **简体中文**

## 开窗：读三样

```
1. memory/README.md       规矩
2. memory/INDEX.md        先看顶部「待复核」和「知识在哪」
3. 最近 3~5 条 entries/   上次聊到哪
```

**不用全读。** 索引是拿来「按需去翻」的，不是拿来通读的。
全读一遍的代价是：上下文还没开始干活就用掉一半。

## 中间：当场落盘，不等收尾

**做完一件事、定了什么、查出什么，当场写。** 写一条比补一天便宜。

为什么不能等收尾：

- 进程会崩
- 上下文会满
- 人会突然关机

**「收尾时再写」是一个前置条件，而崩溃不遵守它。**

## 收尾：三件事，顺序不能倒

```
1. 补条目     把这一窗该记的写进 entries/（能当证据的才写长）
2. 重建索引   python tools/build_index.py --root memory
3. 备份       整个目录复制一份，带日期
```

顺序不能反：**索引要建立在补完之后的样子上**；备份要拍的是索引之后的样子。

## 什么时候写什么

| 时刻 | 写什么 |
|---|---|
| 定了一个方案 | `decisions.md` |
| 答应了谁什么 | `commitments.md` |
| 发现一个坑 | `knowledge/` 或 `experience/` |
| 改了一个事实 | `facts/*.yaml`（改 `updated_at`） |
| 一天结束 | `entries/` 一条，别写成流水账 |

## 上下文满了怎么办

**清的是上下文，不是库。**

新窗开起来，读 `README.md` + `INDEX.md` + 最近几条，就接上了。
真正的风险不是「上下文满了」，是「说了没记」——那种才真的丢。

## 别做的事

- 不要每天写一篇「今日总结」凑数；没有结论的那天，不写
- 不要把对话原文整段粘进 `entries/`；要害写清楚，原文放 `assets/`
- 不要手改 `INDEX.md`；改了下次生成就没了
