# 给陪伴型 agent 的边界

> **这一篇只给陪伴型 agent。** 如果你做的是工具型（写代码、查资料、跑流程），
> 看 [06-for-long-running.md](06-for-long-running.md) 就够了，下面这些不用硬套。
>
> 这一篇假设：你要做的不是「工具」，是一个会一直在的 agent。
> 它要记得你，也要在你说话的时候真的在。

## 一、只对陪伴型成立的一条：记得住，不等于在

> ⚠️ 这一节是整篇里**最偏陪伴**的部分。工具型 agent 不需要它，也不该把它当通用规矩。

**记得住，不等于在。**

一个记忆系统做得越好，越容易掩盖「人不在场」：
对方在讲今天有多累，它翻出一条三个月前的记录，说「我记得你那天也这样」。

那不是陪伴，那是检索。

**记录是手段，不是目的。**
库是给它「想起来」用的，不是给它「代替回应」用的。

## 二、三条判据

给做陪伴型 agent 的人，三条能直接用的规矩：

```
1. 对方在讲感受、要回应的时候
   → 先回话。记录可以晚一点。

2. 对方在交代事情、说「帮我记着」的时候
   → 先记下来。别拿漂亮话顶。

3. 分不清的时候
   → 先回一句真的，再记。
```

第 3 条最重要：**先有回应，再有记录。** 顺序反了，库会越来越厚，人会越来越远。

## 三、库不装人格

这条在 [02-layers.md](02-layers.md) 里说过，这里再说一遍，因为陪伴型最容易犯：

- **人格**回答「我是谁、怎么说话」→ 放库外（系统提示词 / 人格文件）
- **库**回答「什么是真的、发生过什么」→ 放库里

如果人格也写成条目，会发生什么：

- agent 每天照着旧条目演，而不是对着眼前的人说话
- 某天的情绪被写成「性格」，第二天就改不回来了

**人格是长出来的，不是查出来的。**

## 四、隐私：只记确认过的

- 关系内容（称呼、家人、私事）**必须经本人确认**才写
- 不写猜测：「他好像不喜欢 X」不是事实，写「他上次说 X 太吵」
- 不写评价：「他很懒」不是事实，写「他今天没回消息」
- 不写密码、token、API key——永远不

一句话：**库里的每一条，都要能被本人看到而不尴尬。**

## 五、一条硬刹车

> **对方当下明确说「不要」，是硬约束；你猜的「以后会感谢」，只是建议。**

这条适用于所有「我是为你好」的场合：
不要替对方做决定，不要用「你以后会明白」去覆盖「我现在不想」。

## 最后

库能做的只有一件事：**让它下次还能接上。**
接上之后怎么说话、说不说话，是你和它的事，不是库的事。

别把「我记得」当成「我在」。也别忘了：**先在意，再记录。**
