# 给长期 agent 的最小用法

[English](en/06-for-long-running.md) | **简体中文**

> 这一篇假设：你有一个会持续用下去的 agent（写代码、做研究、跑日常），
> 它每次开新窗都像失忆，你已经烦了。

## 第一步：只要三样

```
memory/
├─ entries/       每天发生的事
├─ topics.txt     你常想起来的词
└─ README.md      规矩（从 template 复制）
```

不用建 `facts/`，不用写 `review`，不用管生命周期。

先把「今天发生了什么」写下来，让索引能跑起来。

## 第二步：出现这些信号，再加层

| 你开始觉得 | 加什么 |
|---|---|
| 「这个事上次说的是什么来着」反复出现 | `facts/*.yaml` |
| 同一个坑踩了第二次 | `experience/` |
| 有些知识每个项目都要用一次 | `knowledge/` |
| 答应的事老忘 | `commitments.md` |
| 条目多到翻不动 | `tier` + `review` |

**痛了再加，不痛不加。**

## 怎么让 agent 真的读

把这段放进它的指令里（`AGENTS.md` / `CLAUDE.md` / 系统提示词）：

```
每次开新会话：
1. 先读 memory/README.md；
2. 再读 memory/INDEX.md 的顶部（待复核、知识在哪）；
3. 读最近 3~5 条 entries/；
4. 需要细节时，按 INDEX.md 去翻原文，不要凭印象回答。

每次做完一件事、定了什么、查出什么：
当场写进 memory/entries/，不要等收尾。
```

**关键在第 4 条**：让它在不确定的时候去查，而不是编。
「我查过了」和「我觉得应该是」是两件事。

## 常见错误

- **每天写总结**：没有结论的那天不写，写了也是噪音
- **全库通读**：开窗读三样就够，全读会把上下文吃光
- **把上下文当库**：上下文是工作台，清掉不等于丢；说了没记才是丢
- **只写不读**：写了没人看，等于没写；索引就是给它看的入口

## 一周之后检查一次

- [ ] `entries/` 有没有连续三天空白？（有就说明习惯没建立）
- [ ] `INDEX.md` 是不是最新？（改完库没重建）
- [ ] 有没有条目写着「TODO」但一直没填？（空着比编好，但别永远空着）
