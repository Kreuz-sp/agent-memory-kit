# 为什么用文件

## 上下文不是记忆

模型的上下文窗口是工作台，不是仓库。
窗一关，工作台就清了——下一窗的 agent 只看得见你重新贴进去的东西。

所以「它记得我」这件事，从来不是模型的能力，是**你有没有把东西放在它下次能找到的地方**。

## 文件式的四个好处

| 好处 | 具体是什么 |
|---|---|
| 可读 | 打开就能看，不需要任何工具 |
| 可 diff | 每一次改动都能看见，谁改的、改了什么 |
| 可迁移 | 换模型、换框架、换机器，库跟着走 |
| 可审计 | 每条都有出处；没有出处的，就是谣言 |

## 什么时候不该用文件

- 条目到几万条，靠目录翻不动 → 需要检索层
- 需要语义相似度（「找跟这个意思相近的」）→ 向量库
- 多人同时写、需要锁 → 数据库

**先文件，后检索。** 大多数个人 agent 一辈子到不了「几万条」，先上向量库通常是给自己找活。

## 和向量库的关系

文件是**源**，向量是**缓存**。

顺序别反：先把文件写好，需要的时候再从文件里建索引。
反过来（先建向量库、文件随便写）会有两个后果：改了一条，向量没更新；想核对原文，找不到。

## 一句话

**记忆不是模型记住的，是你放在它下次能找到的地方的。**
